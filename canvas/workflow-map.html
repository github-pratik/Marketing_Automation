The shape of it

The two halves join only through the Sheet

Nothing calls across from intake to outreach. Intake finishes by writing a row to the Leads tab; outreach starts by reading one. That row is the entire interface between them — which is why the channel_state_email column disagreeing once meant every staff-typed lead landed correctly and was never picked up.

Solid lines are direct workflow calls. The dashed line is the outside world calling in. Everything in Band B can spend money or reach a real person.

The send path

Numbered because it genuinely is a sequence — each one hands to the next. Only two of the six have their own clock; the other four run only when called, once per lead.

01
VIO-inbox-mapper every 2 min the front door for human-typed leads

Reads the Inbox tab and normalises whatever shape staff pasted onto the Leads schema, using a deterministic table of about sixty header spellings. OpenAI is called only when a required field is still missing and there are unrecognised columns that might hold it — so a row still being typed is left alone, but a sheet whose email column is named Contact Point still gets read. Blank status is the claim marker. Also stamps the System tab so staff can see the poller is alive.

Listeners — the outside world calling in

No clock. Each sits on an authenticated webhook and does nothing until something happens out there. Together they are the only way the system learns what its mail did.

Instantly reports opens, bounces and unsubscribes here. Bounces and unsubs are appended to Suppression, which is append-only and matches on any identifier — so a person who opts out is out across every product, permanently.

Shelf 3 of 4 · 3 workflows

Operator tools — you run these by hand

They exist so the Sheet can be inspected and corrected without opening n8n. Nothing calls them; they wait on a webhook until you do.

VIO-sheet-audit on demand what does the sheet actually look like

Reads all nine tabs and reports their shape. Two things to remember when reading its output: it derives headers from data rows, so an empty tab reports zero headers whether or not a header row exists — that is how a completely unprovisioned Inbox went unnoticed — and a throttled read can look like a missing tab.

HookPOST /vio-sheet-audit
Readsall 9 tabs
VIO-sheet-provision on demand creates tabs and their header rows

Needs alwaysOutputData on the create step, because creating a tab that already exists returns 400, emits zero items, and stops the chain — while still reporting success. And an append cannot bootstrap a header row: it reads the existing header to decide where values go, so on a bare tab it matches nothing and returns 200.

HookPOST /vio-sheet-provision
Writescreates tabs · Inbox · System
VIO-sheet-repair on demand the manual override

Three actions. seed puts a test row in. approve moves a lead's state — and now takes an optional state, restricted to the sheet's own vocabulary, which is how last night's confirmed-but-unrecorded sends were written back as enrolled. cleanup deletes test rows, guarded to .invalid / .test / .example domains so it can never reach a real prospect.

What the map makes obvious

Two things worth deciding on

Apollo is fully built and fully disconnected

Sourcing, credit-conserving reveal, and the gated reveal tool all exist and are tested. But the only workflow that calls them is VIO-run-campaign, which has a webhook and no scheduler and nothing that posts to it. Every lead in the system today arrived because a person typed it into the Inbox tab. Connecting that leg is one scheduler and one Execute Workflow node — it is the largest capability sitting idle.

The human approval click was removed on purpose

If someone reads this map and asks why the Slack-gated send path is dark: it was replaced, not broken. VIO-enrol-email holds five checks that throw instead of one person clicking Approve. Worth revisiting only if a check turns out to be too loose — the gated path is still there to switch back to.
