Outbound Wiring Map

Where the Sendr link is lost on its way into the email, which workflow talks to which, and what each one actually writes to the Sheet.

The Sendr link never reaches the sent email

The engine already supports it — assemble_email() takes a page_url and swaps the generic CTA for the lead's own Sendr page. That's why Pratik's seed draft carries a real sendrpage.com link. But the thing that actually sends is Instantly, and the URL never gets that far.

What the prospect receives today is the static CTA. The personalized page gets generated and stored, and then nothing links to it from the email.

Three changes to close it

  1. Generate the page before enrolling. Run push_to_sendr_page.py on verified leads first, so sendr_page_url exists on the record before it reaches Instantly. Only on leads that passed verification — pages cost Sendr quota.
  2. Carry the URL into Instantly as a per-lead custom variable, alongside personalization. I'd confirm the exact payload key against the live API before writing it — the leads endpoint has already surprised us twice.
  3. Point the campaign template's CTA at that variable instead of the hardcoded link, with a fallback. A lead missing a page would otherwise render "…for Acme Corp:" followed by nothing — a broken sentence in the most important line of the email. Simplest safe rule: enroll only leads that already have a page URL.

How the pieces actually connect

The important thing to know before reading the map: no n8n workflow calls another n8n workflow. There are six independent workflows, each with its own trigger, plus a Python engine that runs from the command line. What connects them today is a person, or the engine — not n8n.

The Sheet is designed as the data bus, but only the first stop is plugged into it. A lead gets sourced, deduped, suppression-checked, verified and written. Then a page is generated, an email sent, a reply received — and the row never learns about any of it.

The operator agent is the piece meant to tie these together — it can call other workflows as tools, and that's how generate-page and the intake flow would end up on one thread instead of six. Only one tool is attached today, so it can validate a config and little else.

Order I'd build it in

  1. Sendr URL into the email. Highest value per hour — the personalized page is already being built and nothing points at it.
  2. Reply workflow writes to Suppression. This is the compliance one. An opt-out that only reaches Slack is an opt-out that will be contacted again on LinkedIn.
  3. Page + event workflows write back to Leads. Turns the Sheet into a dashboard you can actually read a lead's state from.
  4. Costs metering. Nothing writes it, so the pilot has no cost-per-meeting number.
  5. Attach real tools to the operator agent — the point at which six islands become one pipeline.

One trap for whoever does the Sheet work: the live column order does not match the schema doc — lead_id is column P, not A. The Sheets node matches on header text, so read the header row and match by name. Never address these tabs by A1 letters.
