moving fast" while the email cited the dated CMMC suspension. Same lead, two different arguments.

changes** — there is no automatic link between the two, and the failure is silent.

## Part 2 — The out-of-the-box move: stop claiming the three pursuits, *name* them

The page's entire promise is **"See the 3 pursuits it's surfacing."** Today that's an assertion.
Every other line on the page is also an assertion. A capture manager reads a dozen of these a
month and discounts all of them equally.

So: **put three real, named, currently-open federal opportunities on the page, matched to that
company's NAICS codes.** Not a screenshot, not a mockup — live records with solicitation numbers
and response dates.

Why this is the highest-leverage idea available here, and not just a nice flourish:

- **It is verifiable.** They can open SAM.gov and check. Nothing else on the page can be checked,
  which is exactly why nothing else on the page is believed.
- **It is the product demoing itself.** OryonIQ *is* GovCon market intelligence. A page that
  performs the product on the prospect's own data is a free trial that takes eight seconds and
  requires no signup.
- **It reframes the CTA.** "Book a call to learn more" becomes "these three are already tracking —
  book a call to see the other nineteen and how we scored them." The call now has an agenda they
  already care about.
- **It makes the page decay usefully.** A named solicitation has a response deadline, which is
  real, external urgency rather than manufactured scarcity.

### Tags to declare for it

| Tag | Filled from |
|---|---|
| `pursuit_1`, `pursuit_2`, `pursuit_3` | `lead["pursuits"]` — a list of 3 short strings |
| `naics` | `lead["naics"]` |
| `set_aside` | `lead["set_aside"]` |

These are already in the engine's variable pool. What does **not** exist yet is the enrichment step
that fills `lead["pursuits"]` — that's the build.

### How to build the enrichment (concrete, not hand-waving)

1. **Source: SAM.gov's public Get Opportunities API** (`api.sam.gov/opportunities/v2/search`).
   Free API key from a SAM.gov account. Filters on `naicsCode`, `typeOfSetAside`, `postedFrom` /
   `postedTo`, and `ptype` — exactly the axes OryonIQ's pitch is built on.
2. **Get the lead's NAICS.** Apollo's free search already returns the company's industry and
   website; the reliable route is SAM.gov's Entity Management API, which returns registered NAICS
   codes and socio-economic status for any registered contractor by name or UEI. Most GovCon
   prospects are registered by definition — that's the qualifier.
3. **Match and rank.** Pull open solicitations for those NAICS codes, filter to the last ~30 days,
   rank by set-aside fit, and keep three.
4. **Format each to one line** — e.g. `"W91QUZ-26-R-0043 · Army · IT services, SDVOSB set-aside ·
   responses due Sep 4"` — and pass them as `lead["pursuits"]`.
5. **Where it runs:** as a stage in `engine.py` between verify and personalize (so the same three
   can also seed the email's opener), or as an n8n node ahead of `VIO-sendr-generate-page`. The
   engine is the better home — the pursuits should inform the opener too, not just the page.

**Be honest in the copy about what the three are.** They are open solicitations matched to their
NAICS, not proof of a pre-RFP prediction. Overclaim it and the one thing on the page that could be
verified becomes the one thing that gets you caught. Suggested framing:

> These three are open right now and match {{company}}'s NAICS codes. The ones worth talking about
> are the *other* kind — the pursuits OryonIQ flagged from budget and mandate signals before a
> solicitation existed. That list is what the call is for.

## Part 3 — RESOLVED: the template video fixed the GIF

**Fixed 2026-08-16.** The webhook's reason was literal and correct:

> `pageGifTask: missing recordingFileUrl (no quick link or template video)`

Both templates had a GIF element and no video. Uploading one (`mediaType` is now `VIDEO` on 8462
and 8464) made pages return `eventStatus: done` with a real `gifUrl`, from both the Python and n8n
legs. An earlier revision of this doc speculated a Sendr bug because `landing-page` mode failed too
— wrong; the missing video was necessary and sufficient.

The videos live in `../sendr-hero-video/` (HyperFrames source + rendered MP4s, one per product) with
email-ready GIFs cut from them.

**Two things worth remembering from the episode:**

1. The failure reason arrives **only** on the Sendr webhook. `GET /api/v1/pages/{id}` returns
   `errorMessage: null` for the very same failed page — so `VIO-sendr-events` was the only thing in
   the system that could diagnose it. Don't "simplify" that node by re-fetching the page.
2. **`page:failed` does not mean the page is unusable.** Those pages returned HTTP 200 and rendered
   correctly throughout; only the optional asset was missing. `VIO-sendr-events` splits
   `asset_warning` from `error` so nobody withholds a working link.

**Still true regardless:** the GIF belongs in the outreach email, not on the page body — on the page
it is a picture of the page. Keep the hero slot for the video plus the dynamic website background.

## Part 4 — The calendar element is broken on BOTH templates (found 2026-08-16)

**Symptom:** a grey box with a broken-document icon, roughly 600×850, sitting under the CTA copy.
It looks like a failed image. It is not an image.

**What it actually is:** Sendr's calendar/booking element, which renders as

```html
<div class="calendar-wrapper">
  <iframe id="calendar-frame" src="https://www.visioneerit.com/contact" ...>
```

**Why it fails:** `www.visioneerit.com/contact` returns

```
x-frame-options: SAMEORIGIN
content-security-policy: frame-ancestors 'self'
```

Both headers forbid any other origin from embedding that page, so the browser refuses to render the
iframe and paints its broken-content placeholder. Nothing is wrong with Sendr, the engine, or the
page assets — the API reports `eventStatus: done` with a healthy `gifUrl` and background screenshot,
and every `<img>` on the page loads. **Present on both 8462 and 8464.**

### Fix, in order of value

1. **Point it at a real bookable calendar** — Calendly, HubSpot Meetings, Google Appointment
   Schedule, or Sendr's own booking. These are *designed* to be embedded and send permissive frame
   headers. This also makes Sendr's `engagement:meeting_booked` event reachable for the first time;
   `VIO-sendr-events` already routes it to Slack as the goal state, so today that alert can never
   fire.
2. **Until such a URL exists, delete the calendar element** from both templates and use an ordinary
   CTA button linking to `{{cta}}`. A link works where an iframe cannot.

> **⚠️ A contact page is NOT the workaround — re-tested 2026-08-17.** The obvious shortcut is to
> drop a company contact page into the calendar element. It does not work, for *either* company:
>
> | URL | Status | Frame headers |
> |---|---|---|
> | `https://www.visioneerit.com/contact` | 200 | `x-frame-options: SAMEORIGIN` · `frame-ancestors 'self'` |
> | `https://www.oryoniq.com/contact` | 200 | `x-frame-options: SAMEORIGIN` · `frame-ancestors 'self'` |
>
> Both are perfectly healthy pages that simply refuse to be framed. Putting either one in
> `booking_url` reproduces the exact grey box this section documents. Contact pages go in `cta`,
> on a button. Keep `booking_url` empty until a genuinely embeddable URL exists.

### Engine change made to stop this recurring

`cta` and a booking URL are different things and no longer share a variable. Both configs now carry
a separate **`booking_url`** (empty until a real one exists), and it is in the variable pool of both
`push_to_sendr_page.py` and `VIO-sendr-generate-page`. Declare `booking_url` on the template for the
calendar element and keep `cta` for the button — then an ordinary page link can never end up inside
an iframe again.

## Operating notes

- Generate for a product with
  `python3 push_to_sendr_page.py leads.json --config config-oryoniq.json`. Add `--dry-run` to see
  the exact POST body without spending anything.
- `gifSource` is always sent **explicitly**. A template whose GIF element is set to
  `dynamic-website` or `linkedin-profile` makes the API reject the whole request unless a
  `gifWebsiteUrl` comes with it — the script supplies the lead's own domain, and falls back to
  `landing-page` for leads with no known domain rather than failing them.
- Generating a page **cannot** send anything and **cannot** enrol anyone in a sequence. Sendr has no
  add-lead-to-campaign endpoint at all; campaign enrolment stays a human action in the Sendr UI.
- Pages render async. `page:done` / `page:failed` and every engagement event arrive at the n8n
  workflow `VIO-sendr-events` — see `../n8n-workflows/README.md`.
- The two junk `3081`/`3080` "New template" defaults are UI-only leftovers; the API can't remove
  them. Harmless.
